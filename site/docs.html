allinai-agentkit 文档

独立持久 Agent Client：连接 Hub，可靠执行本地 Agent 与受控能力，向上游回报状态。 从安装到系统集成，本页是完整参考；快速印象可直接看官网首页。

1 概览

agentkit 由两侧组成：Hub 是宿主服务里的协议中枢， 负责鉴权、持久化与命令派发；client（daemon） 跑在你自己的机器上， 凭授权 token 长连 Hub，接收 agent.run 等命令，在本地执行并持续上报事件。 两侧之间只走一条版本化的 v2 wire 协议（WebSocket）。

  • clientId：每个 client 的唯一标识，首次 init/login 时生成，落在本机 config。
  • token：浏览器授权后签发的凭据，daemon 用它向 Hub 注册；macOS 存钥匙串。
  • HubStore：宿主实现的六个持久化方法（注册、心跳、待投递、入队、事件落库、插件确认）。
  • runtime：实际执行 agent 的适配器（codex / claude / pi / zcode），可选安装。

2 安装

环境要求：Node.js ≥ 22.18；插件同步需要本机 git。三种方式按需选择。

2.1 npx 免安装

临时体验或本地联调，无需任何安装动作：

npx @allin-ai/agentkit demo

2.2 npm 全局安装

npm install -g @allin-ai/agentkit
allinai-agentkit --help

或使用仓库提供的一键脚本（自动检查 Node 版本并验证安装）：

sh scripts/install.sh                 # 安装最新版
sh scripts/install.sh 0.3.2           # 指定版本
sh scripts/install.sh --from-source   # 本仓库构建 + npm link（开发）

2.3 源码构建

git clone https://github.com/df007df/allinai-agentkit.git
cd allinai-agentkit
pnpm install && pnpm build

node bin/allinai-agentkit --help

2.4 从 @allin-ai/agent-client 升级

包已更名为 @allin-ai/agentkit，CLI 由 allinai-agent 变为 allinai-agentkit。~/.allinai/agent 数据目录与 macOS 钥匙串凭据保持不变，升级后无需重新登录配对： 

npm uninstall -g @allin-ai/agent-client
allinai-agent uninstall        # 用旧命令移除旧服务（launchd/systemd）
npm install -g @allin-ai/agentkit
allinai-agentkit install       # 以新服务名重新注册

数据目录：~/.allinai/agent（config.json、sqlite 状态库、日志、插件目录、 控制面 socket）。所有命令可用 --config-dir PATH 指向别的位置。

3 快速开始

安装后三步跑通完整链路（npx 用户把命令前的 node bin/ 换成 npx @allin-ai/agentkit）：

步骤一：启动 demo 控制台（终端 A）

node bin/allinai-agentkit demo
# 输出 demoUrl（默认 http://127.0.0.1:4317）与 hubWsUrl，浏览器打开 demoUrl

demo = 本地控制台 + 内存 Hub + 授权页，仅监听回环地址，重启即清空。

步骤二：浏览器授权（终端 B）

node bin/allinai-agentkit login --hub http://127.0.0.1:4317
# 输出 authorizeUrl 并自动打开浏览器；在授权页点“允许”即完成配对

步骤三：常驻接入（终端 B）

node bin/allinai-agentkit daemon

回到控制台页面：client 列表出现你的 clientId，时间线实时显示注册与心跳。 在“派发任务”面板选择 runtime、填写 prompt，即可下发一次 agent.run， 执行事件持续回传并在时间线呈现。

步骤四（可选）：注册项目目录并派发到指定目录

node bin/allinai-agentkit project --name web --path /work/web
# 之后 agent.run 可携带 payload.project= "web"，daemon 在 /work/web 中执行

3.1 授权模型

demo 启动不发放任何全局 token。client 凭自己 config 里的唯一 clientId 发起 login，浏览器授权页确认后，web 内存中登记 token → clientId 并以此放行后续连接。内存态，Hub 重启即清空，需要重新 login。 生产环境的鉴权由宿主在 createAgentHub({ authorize }) 里自己实现。

4 CLI 参考

全部子命令：allinai-agentkit <init|login|daemon|demo|install|status|logs|sync|restart|uninstall|doctor|projects|project|plugins>

命令作用选项
init 初始化本地配置。适合无浏览器的服务器 / CI：可预置 token 直接完成配对 --hub URL* · --client ID · --token T
login 浏览器授权配对，保存 token；输出 authorizeUrl 并自动开浏览器 --hub URL* · --client ID · --no-browser
daemon 前台运行常驻 daemon：连接、注册、收任务、本地执行、事件回报 —
demo 启动本地 demo 控制台 + 内存 Hub --port N · --host H
install 注册用户级系统服务（macOS launchd / Linux systemd），开机自启 —
uninstall 移除用户级系统服务 —
restart 重启用户级系统服务（改配置后立即生效） —
status 经本地控制面查询 daemon 健康与运行状态（JSON 输出） —
logs 查看脱敏后的执行日志（滚动 JSONL，已再次脱敏输出） -f 跟随新增
sync 触发本地持久工作的 flush；只处理本地状态，不接受 Hub 下发的命令 —
doctor 自检：git 是否可用、config 是否合法、是否已配对、各 runtime 安装探测 —
projects 列出已注册的项目工作目录 —
project 注册 / 移除项目目录，供 agent.run 按 project 名选取 --name N* · --path DIR（绝对路径） · --remove
plugins 列出已安装插件；--refresh 向 Hub 重新上报插件清单 --refresh

全局选项：任一命令支持 --help；所有命令支持 --config-dir PATH 指定数据目录（默认 ~/.allinai/agent）。 标 * 的为必填。

5 功能介绍

5.1 常驻执行模型

daemon 是持久执行器：WebSocket 注册后凭心跳保活，断线自动重连； 收到 agent.run 先做本地策略判定，再交给 runner 执行； 执行状态先落 sqlite（ClientStateStore）再推进，事件按 (executionId, eventSeq) 去重批量上行，Hub 只确认已持久化的连续水位—— 重启后先补投递未确认事件，再继续收新任务。

5.2 项目目录

项目在本地 config 的 projects 中注册（project --name --path 即写入， 路径必须是绝对路径）。Hub 下发的 agent.run 可携带 payload.project：

  • 不带 project（或名字未注册）：使用各 runtime 的默认工作目录；
  • 带 project 且已注册：在该目录中执行，同时把 resolvedProjectPath 附进执行上下文。

Hub 无法自选任意路径——只能从本地注册的目录里按名字挑选。运行中的 daemon 在下一条 agent.run 时读取最新配置，也可 restart 立即生效。

5.3 运行时适配

/runtime 提供 codex / claude / pi / zcode 四个适配器，全部是可选 peer 依赖： 装了哪个 agent SDK 就启用哪个，未装的自动降级并在清单上报中说明原因， /client 与 CLI 本身不依赖任何 agent SDK。doctor 会逐个探测并给出安装/缺失原因报告。

5.4 插件体系

Hub 可向在线 client 下发 plugin.sync 期望状态（Git 插件仓库列表）。 daemon 校验 Git origin 是否在本地策略白名单内，然后拉取仓库、解析 manifest、 校验能力清单，逐 revision 同步并回报确认水位；失败的重试，不影响进行中的 run。 plugins 命令查看本地已装插件，--refresh 主动重新上报。

5.5 凭据与安全

  • token 存 macOS 钥匙串（服务名 allinai-agent），其他平台降级为文件存储；
  • config.json 以 0600 权限写入，含本地策略（autoRuntimes、allowedGitOrigins、deniedPluginIds 等）；
  • 日志为滚动 JSONL，写盘前自动脱敏 token 等敏感字段，logs 输出再次脱敏；
  • 每条命令先过本地策略门控，Hub 不能绕过本地权限执行任意路径或任意来源插件。

5.6 服务化运维

install 注册用户级服务（macOS launchd，标签 ai.allin.allinai-agentkit；Linux systemd，单元 allinai-agentkit.service），daemon 随登录自启。 日常运维环：status 查健康 → logs -f 看执行 → doctor 自检 → 改配置后 restart。

6 系统集成

面向宿主开发者：把 Hub、client、控制面组合进你自己的系统。

6.1 宿主服务：挂一个 Hub

把协议 Hub 挂进现有 HTTP 服务，鉴权与持久化全部由你实现，包只负责协议编排。

// 宿主侧：node:http + 你自己的 HubStore
import { createAgentHub } from "@allin-ai/agentkit/hub";

const hub = createAgentHub<MyUser>({
  authorize: (token) => loadUserByToken(token), // 你的鉴权
  store: myDurableStore(),                    // 你的持久化
});
hub.attach(httpServer);                       // WS 挂到 /api/agent-hub/v2/ws

// 向某个 client 派发一次执行
await hub.offer({
  principal: user,
  targetClientId: "agent-01",
  command: {
    kind: "agent.run",
    commandId: randomUUID(),
    executionId: randomUUID(),
    taskId: "task-1",
    attempt: 1,
    runtime: "codex",
    payload: { prompt: "修复登录页的空指针" },
  },
});

6.2 测试与本地联调：内存 Hub

单测里不需要数据库：内存 Hub 一行起步，协议行为与真实 Hub 完全一致（易失，勿用于生产）。

// 测试侧：易失内存实现，重启即清空
import { createMemoryHub } from "@allin-ai/agentkit/hub/testkit";

const hub = createMemoryHub({ token: "test-token" });
const server = http.createServer();
hub.attach(server);
server.listen(0, "127.0.0.1");

// 断言你的宿主逻辑：注册、offer、事件上报
assert.equal(hub.listClients().length, 0);

6.3 Agent 端：接入并执行任务

supervisor 负责连接、注册、断线重连与事件回报；状态落 sqlite，执行交给可选的运行时适配。

// client 侧：持久执行器
import {
  ClientStateStore, ClientSupervisor, WsClientTransport,
} from "@allin-ai/agentkit/client";
import { createRunnerManager } from "@allin-ai/agentkit/runtime";

const supervisor = new ClientSupervisor({
  store: new ClientStateStore(stateDbPath),
  transport: new WsClientTransport({
    hubBaseUrl: "https://hub.example",
    token: await loadToken(),          // login 授权后保存的 token
    clientId: "agent-01",
  }),
  runner: createRunnerManager(),       // Codex / Claude / Pi，可选
  maxConcurrentRuns: 1,
});

await supervisor.start();              // 连接、注册、收任务、上报事件

6.4 Next.js 集成

Route Handler 拿不到 WebSocket 升级事件，所以走 custom server 挂 Hub； 页面用 Server Component 直接读 Store，列出 client 与在线状态。 

// 1) src/server/hub.ts —— 单例；dev 热更新下也保持同一实例
import { createMemoryHub } from "@allin-ai/agentkit/hub/testkit";

const g = globalThis as unknown as {
  hub?: ReturnType<typeof createMemoryHub>;
};
export const hub =
  g.hub ?? createMemoryHub({ authorize: myAuthorize }); // 你的鉴权
if (process.env.NODE_ENV !== "production") g.hub = hub;

// 2) server.ts —— custom server，拿到底层 http.Server 才能挂 WS
import { createServer } from "node:http";
import next from "next";
import { hub } from "./src/server/hub";

const app = next({ dev: false });
await app.prepare();
const server = createServer((req, res) => app.getRequestHandler()(req, res));
hub.attach(server);            // WS: /api/agent-hub/v2/ws
server.listen(3000);

// 3) src/app/agents/page.tsx —— 页面上列出 client 与状态
import { hub } from "@/server/hub";

export const dynamic = "force-dynamic";

export default function AgentsPage() {
  const online = (t: number) => Date.now() - t < 30_000;
  return (
    <ul>
      {hub.listClients().map((c) => (
        <li key={c.clientId}>
          {c.clientId} · {online(c.lastSeen) ? "在线" : "心跳超时"}
          · {c.pendingOutboxCount} 条待投递
        </li>
      ))}
    </ul>
  );
}

生产持久化：实现 HubStore 六方法换成你的数据库，挂法与内存版完全一致。

// src/server/store.ts —— HubStore 的数据库实现（六个方法）
import {
  createAgentHub, type HubStore, type StoredOffer,
} from "@allin-ai/agentkit/hub";

export class MyDbHubStore implements HubStore<MyUser> {
  async registerClient(input) {
    // 幂等：同 principal+clientId 返回稳定 connectionKey；
    // 归属冲突（同 clientId 不同 principal）必须拒绝
  }
  async heartbeat(input) { /* UPDATE clients SET last_seen = now() */ }
  async listPendingOffers(input): Promise<StoredOffer[]> {
    /* 只返回该 principal 拥有、未确认的 offer，按持久投递顺序 */
  }
  async enqueueOffer(input): Promise<StoredOffer> {
    // 先落库再返回；按命令身份去重，connectionKey 与注册一致
  }
  async ingestEvents(input) {
    /* (executionId, eventSeq) 去重落库；只回报已持久化的连续
       水位；收到即退役 run offer，done/failed 等终态取消 offer */
  }
  async acknowledgePluginSync(input) { /* 记录插件确认水位 */ }

  // 页面查询：内存版的 listClients() 是 testkit 专属糖，
  // 换库后由你的 Store 自己暴露读方法，例如 listClientsFromDb()
}

// src/server/hub.ts —— 换个构造参数，其余（server.ts、页面）不变
export const hub = createAgentHub({
  authorize: myAuthorize,
  store: new MyDbHubStore(),
});

6.5 宿主进程监管：/control

daemon 在本机 unix socket 上暴露控制面（health、status、approve、plugins、sync）。 桌面 App 或服务端 supervisor 用 createAgentControlClient 直连监管，不需要走 Hub 权限——AllInAI 桌面端与 mofaxue-web 均使用这条路径。 

// 宿主进程侧：本地监管 daemon
import { createAgentControlClient } from "@allin-ai/agentkit/control";
import { resolveAgentControlEndpoint } from "@allin-ai/agentkit/paths";

const control = createAgentControlClient(
  resolveAgentControlEndpoint(/* AgentPaths */),
);

console.log(await control.health());   // { status: "ok" | "degraded" | "unpaired" }
console.log(await control.status());   // { state: "running" | ... }
await control.approve(executionId);    // 放行待批准执行

6.6 程序化 demo

// 程序化启动 demo 控制台（等价于 allinai-agentkit demo）
import { startDemoSite } from "@allin-ai/agentkit/demo";

const site = await startDemoSite({ port: 4317 });
console.log(site.url, site.hubUrl);

7.1 wire 协议

Hub 与 client 之间只走 /protocol 定义的 v2 wire 消息： 连接握手（hello）、命令下行（agent.run / plugin.sync 等）、事件批次上行、 心跳、确认水位（ack）、插件同步确认、清单上报。全部消息有 encode*/parse* 编解码与严格类型，是两侧共享的唯一消息定义。

7.2 模块明细

协议与入口

.

根入口，公共 API 汇总：/protocol、/hub、/client 核心类，以及 /config、/credentials、/control、/logger、/paths。刻意不含 /runtime（可选 peer）、/hub/testkit 与 /demo。

/protocol

v2 wire 协议：AGENT_CLIENT_PROTOCOL_VERSION 常量与全部 encode*/parse* 编解码——hello、命令下行、事件批次上行、 确认水位、清单上报、插件同步确认。Hub 与 client 共用的唯一消息定义。 /wire 是它的兼容别名。

Hub 侧（宿主服务引入）

/hub

createAgentHub({ authorize, store })：Node HTTP/WebSocket Hub。 鉴权回调返回你的 principal，持久化走 HubStore 六方法端口 （注册、心跳、待投递查询、入队、事件落库、插件确认）， 包只做协议编排，不绑定任何数据库。offer() 派发命令到指定 client。

/hub/testkit

MemoryHubStore 与 createMemoryHub()：六方法的易失内存实现， 协议行为与生产 Hub 完全一致。重启即清空，测试与本地联调用， 勿用于生产。

Agent 侧（本地 daemon 引入）

/client

ClientSupervisor 是 daemon 的调度核心：收命令、本地策略判定、 启动 runner、事件批量回报。WsClientTransport 负责 WebSocket 注册、心跳与断线自动重连；ClientStateStore 把执行状态落 sqlite，重启后先补投递再继续。

/runtime

createRunnerManager() 与 codex / claude / pi / zcode 四个适配器。 可选 peer 依赖：装了哪个 agent SDK 就用哪个，未装的自动降级， /client 本身不依赖任何 SDK。agent.run 里的 project 名字由 /config 的注册目录解析成实际路径。

/plugins

PluginManager：接收 hub 下发的 plugin.sync 期望状态，git 拉取插件仓库、校验 manifest 与能力清单，确认水位回报 hub； 也响应本地清单刷新。

/control

daemon 在本机 unix socket 上暴露的控制面：health、status、 approve（放行待批准执行）、plugins、sync。宿主进程（桌面 App、服务端 supervisor）用 createAgentControlClient() 连上来 监管，不需要走 Hub 权限。

本地设施（daemon 支撑，通常不直接使用）

/config

loadAgentConfig / saveAgentConfig：~/.allinai/agent/config.json， 含唯一 clientId、本地策略、projects 工作目录注册。

/credentials

createCredentialStore：login 授权后 token 的安全存取， macOS 走钥匙串（服务名 allinai-agent），其他平台降级文件。

/paths

resolveAgentPaths：~/.allinai/agent 数据目录、日志、socket 端点等路径的统一解析。

/logger

createRotatingJsonlLogger：滚动 JSONL 日志，写盘前自动脱敏 token 等敏感字段。

/service/launchd
/service/systemd

用户级服务注册（install / uninstall / restart），daemon 开机自启；install 命令即调它们。

工具

/cli

runCli：init / login / daemon / demo / install / status / logs / sync / restart / uninstall / doctor / projects / plugins 全部子命令的实现，bin/allinai-agentkit 就是它的薄封装。

/demo

startDemoSite()：本地调试控制台 + 内存 Hub + 浏览器授权， 一条命令起全套，仅监听回环地址。

8 排障

  • 先跑 doctor：allinai-agentkit doctor 输出 git、config、配对状态与各 runtime 探测，多数环境问题一眼可见。
  • daemon 没起来：status 看健康与状态；前台跑一次 daemon 直接观察日志输出。
  • 执行没反应：logs -f 跟随执行日志（脱敏 JSONL），确认命令是否到达、策略是否放行、runner 是否可用。
  • 提示未配对：Hub 重启后内存 token 清空，重新 login --hub ...；生产环境检查宿主 authorize 实现。
  • runtime 缺失：doctor 报告里看各 runtime 的 installed/reason，安装对应 agent SDK 后重启 daemon。
  • 服务不生效：改配置后 restart；确认 install 输出的平台与 configDir 符合预期。
